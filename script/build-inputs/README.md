# Build inputs — not translation files

Nothing in this folder is text you translate. These are the measured facts and declared
patches the inserter needs in order to place English safely, and the build fails or
mis-places text without them.

**If you are translating the game, you can ignore this folder entirely.** The files you
edit are one level up: `script/prose_draft.tsv` for dialogue, `script/en.tsv` for menus and
labels, `script/intro.tsv` for the opening cinematic, and `script/glossary.tsv` for names.
`../README.md` is the guide.

| File | What it records | Read by |
|---|---|---|
| `box_geometry.tsv` | Menu box geometry — each box's measured x, y, rows and width, so the fitter knows what can physically fit | `build.py`, `fontaudit.py` |
| `box_alias.tsv` | Menu boxes that render *another* box's text, which makes their own text bytes free space | `build.py` |
| `reloc_ok.tsv` | Which copy loop reads which pointer table — the attribution deciding whether a string may be redirected into the pool | `build.py` |
| `dte_ok.tsv` | Strings observed being read by a loop that expands DTE. Evidence, not a guess: generated by `gbrun.py <rom> --dte-scan` | `dte_rom.py`, and through it `build.py` |
| `raw_patches.tsv` | Direct byte patches for text packed inside a composite string, where no terminator marks its boundary | `build.py` |
| `tile_patches.tsv` | Labels drawn as bitmaps rather than text characters, such as the status bar's own mini-font | `build.py` |

Each file's own header comment is authoritative on its format and on why its rows are
allowed to exist. Read that before adding a row.

A run of `00` or `FF` bytes is not evidence that a span is free — see
`docs/ROM_BANK_MAP.md` before moving anything these files point at.
